# Deck 身份独立于文件路径

Editor 将 Deck 视为具有稳定 `deckId` 的逻辑文档，把当前 HTML 路径降为可变化的文件绑定。选择该方案是因为路径主键会在外部改名后同时破坏任务历史、Session 恢复和固化目标，而内容哈希又会在每次合法编辑后变化；依赖操作系统强制锁也无法在 macOS 上可靠禁止外部改名。

## Considered Options

- **路径作为身份**：实现简单，但改名等同于删除旧 Deck 并创建新 Deck，无法可靠恢复工作副本和 Agent 上下文。
- **内容哈希作为身份**：适合并发校验，不适合文档身份；每次编辑都会产生新哈希，复制文件还会造成歧义。
- **强制禁止外部改名**：Windows 可以加强限制，但 macOS 普通文件锁是协作式的，跨平台语义不一致且强行修改权限会破坏正常保存。
- **稳定 Deck 身份 + 可变文件绑定**：保留连续工作身份，通过文件见证识别外部改名，无法唯一判断时进入保护状态并要求用户重新绑定。

## Consequences

- 工作项、运行时和编辑会话必须以 `deckId` 或 `workId` 索引，不能继续以路径作为主键。
- 固化必须经过文件绑定闸门，不能直接向启动时保存的路径写入。
- 固化检查点是原子发布成功后的耐久证明；仅当 `deckId`、当前路径、当前源文件指纹与最近检查点全部一致时，才允许用它补偿恢复遗漏的 FileWitness 写回。缺少检查点或任一证据不一致时仍保持冲突。
- 最近任务和既有 Session 需要幂等迁移；旧目录无需因文件改名而搬迁。
- 工作项显示名称与文件名分离，用户修改显示名称不会重命名源文件。
