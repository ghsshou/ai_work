# 编辑历史采用线性游标与补偿修改

Editor 的人工编辑、Agent 动作和结构修改统一写入一条带唯一游标的编辑时间线；全局撤销 / 重做只能移动游标，撤回非末尾 Agent 任务则追加可逆的补偿修改，固化成功后建立检查点并归档此前时间线。这个选择避免旧 `active` 标记制造历史空洞，也避免任意历史 DAG 带来的重放歧义；代价是结构修改仍须严格按顺序撤销，补偿无法证明安全时必须显式报冲突。

## 考虑过的方案

- 保留动作组 `active` 标记和独立 redo 列表：实现简单，但会产生多个不连续生效区间，任务撤回、顶栏重做和固化投影可能互相矛盾。
- 采用任意分支的历史 DAG：能表达更多分支，但用户界面、持久化迁移、结构版本恢复和失败补偿都显著复杂。
- 采用线性游标并把非末尾任务撤回建模为补偿修改：全局历史保持单义，同时保留任务 drawer 的定向撤回能力，因此采用。

## 后果

旧会话迁移时只保留可证明仍生效的顺序历史，无法恢复的旧 redo 空洞进入迁移归档而不再伪装成可重做修改。ActionMutation 可在语义连续性成立时生成补偿；SourceMutation 只允许顺序撤销 / 重做。若后续 SourceMutation 已删除较早 action 的页面或元素，固化器只允许按失败动作 ID 剔除这类已取代动作，并在每次剔除后从头验证；语义、几何和当前值冲突仍然拒绝发布。固化预检与正式写入绑定同一 revision、文件指纹、绑定版本和动作投影，成功后任务关联到新的固化检查点，session 基线采用实际通过验证的补丁集合。

## 源码覆盖旧文字动作的对账

源码事务比较受控归档的前后快照。若同一个持久元素的静态文字已被源码覆盖，事务记录 `actionReconciliation.supersededKeys`，编译投影停止重放对应旧文字动作及失效的字符范围样式；独立样式仍保留。原动作和源版本不删除，撤销源码事务后旧投影重新生效。动态 DOM、重复身份、无法定位或无法证明的样式变化不推测覆盖关系，仍走真实浏览器校验。旧会话在启动时使用相同快照证据补充对账记录，过程不改 Deck 内容。

历史连续性冲突仍拒绝提交；关联任务更新为失败并显示实际错误，不能继续保留先前的“多个目标”待确认提示。
