## 标题

- 眉题：设计态 AI 集群仿真器 · ScaleOut 网络仿真
- 主标题：以拓扑、协议、模组三层仿真支撑十万～五十万卡 ScaleOut 网络设计决策

## 横幅

- 面向场景：面向 10T～50T+ 大模型、约 50 万卡量级集群，在设计态仿真 ScaleOut 网络方案与网卡行为，对照吞吐、延迟与瓶颈
- 竞争力目标：对照 RoCE 与 UBoE 等协议路径，并以 CX model 刻画网卡模组级行为，给出可量化的方案取舍依据
- 技术挑战：超大规模拓扑与路由保真、集合通信与流量跨 ScaleOut 可复现、端侧网卡与网侧交换机行为可插拔

## 待验证问题（左图上方条带）

ScaleOut 带宽设计｜收敛比分析｜拥塞/丢包性能测算｜协议路径吞吐对照｜故障重构影响

## 输入与输出

输入（四类同时抽出）：集群拓扑意图、并行与通信模式、协议与拥塞策略、网卡与模组参数

输出（从执行结果分出四类对照）：带宽延迟对照、集合通信效率、瓶颈定位图、RoCE/UBoE/网卡方案对比

## 核心：自上而下三层

框外短注：自上而下三层；协议层双栈可对照，模组层基于 CX model。

① 基于拓扑意图图的多路径路由仿真

- CLOS/Dragonfly 意图建模
- ECMP 哈希多路径
- 故障域重构推演
- 跨域收敛比测算

② 基于双栈行为模型的流量仿真

- RoCE 拥塞控制模型
- UBoE 转发路径模型
- 集合通信轨迹重放
- PFC/ECN 策略对照

③ 基于 CX model 的端网模组仿真

- CX 端侧延迟链模型
- 182X DMA/门铃映射
- 交换机队列调度模型
- 端网模组插拔接口

## 关键技术

关键技术 1：基于拓扑意图图的多路径交叉验证

1. 意图构图：先从集群拓扑意图生成可扩 CLOS/Dragonfly，再注入路由与故障路径
2. 同负载对照：同一通信负载下对比不同拓扑与路由配置的瓶颈位置

关键技术 2：基于双栈行为模型的协议路径对照

1. 双栈回放：同一流量意图分别注入 RoCE / UBoE 行为模型
2. 事件序重放：集合通信与跨 ScaleOut 流量按事件序回放

关键技术 3：基于 CX model 的端/网侧模组级仿真

1. 模组建模：用 CX model 刻画端侧 DMA/offload 与网侧交换机延迟、吞吐（含 182X 映射）
2. 接口解耦：设备接口固定，换网卡或交换机模型不改上层拓扑与协议层
